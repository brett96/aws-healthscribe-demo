# AWS HealthScribe Demo Project: Detailed Explanation

This document provides a detailed explanation of the AWS HealthScribe Demo project, outlining its architecture, file structure, key functionalities like authentication, and integration with AWS services such as HealthScribe and Comprehend Medical.

## 1. Big Picture: Overview and Purpose

The AWS HealthScribe Demo is a full-stack web application designed to showcase the capabilities of **AWS HealthScribe**. HealthScribe is a HIPAA-eligible service that helps healthcare software vendors generate clinical notes from patient-clinician conversations.

**Core Purpose:**

- Allow users to submit audio recordings (either by uploading a file or recording live).
- Initiate and manage AWS HealthScribe jobs to process these audio files.
- Display the results, which include:
    - A detailed transcript of the conversation, with speaker diarization.
    - Summarized clinical notes (e.g., SOAP or GIRPP notes).
    - Structured medical terms and evidence linking back to the transcript.
- Demonstrate integration with **Amazon Comprehend Medical** for further natural language processing, such as linking medical terms to ontologies (ICD-10-CM, RxNorm, SNOMED CT) and extracting additional medical entities.

**Technology Stack:**

- **Frontend:** React (with TypeScript), Vite for bundling, Cloudscape Design System for UI components.
- **Backend & Infrastructure:** AWS Amplify, which provisions and manages:
    - Amazon Cognito for user authentication.
    - Amazon S3 for storing audio files and HealthScribe job outputs.
    - AWS Lambda for custom backend logic (e.g., setting up S3 bucket logging).
    - IAM roles and policies for secure access to AWS services.
- **AWS Services Used Directly:**
    - AWS HealthScribe: Core service for transcription and clinical note generation.
    - Amazon Comprehend Medical: For advanced medical NLP.
    - Amazon Polly: For generating synthetic audio for demo purposes.
    - Amazon S3: For storage.
    - Amazon Cognito: For user authentication.

The application provides a user-friendly interface for healthcare professionals or developers to see how HealthScribe can be integrated into clinical workflows.

## 2. Project Structure

The project is organized into several key directories:

- **`/` (Root Directory):**

    - `README.md`: Main project overview and setup instructions.
    - `package.json`, `yarn.lock`: Frontend project dependencies and scripts.
    - `vite.config.mts`: Vite build configuration.
    - `tsconfig.json`: TypeScript configuration for the frontend.
    - `index.html`: Main HTML entry point for the React app.
    - `amplify.yml`: Build specification for AWS Amplify hosting.

- **`/amplify`:** Contains all AWS Amplify backend configurations.

    - **`/amplify/backend`:** Defines the cloud resources.
        - `backend-config.json`: Top-level configuration for Amplify categories (auth, storage, function, custom).
        - **`/amplify/backend/auth/healthScribeDemoAuth/`**: Configures Amazon Cognito for user authentication.
            - `cli-inputs.json`: User inputs provided during `amplify add auth`.
            - `override.ts`: Allows customization of the Cognito CloudFormation template (e.g., to shorten token validity).
        - **`/amplify/backend/storage/healthScribeDemoStorage/`**: Configures Amazon S3 for file storage.
            - `cli-inputs.json`: User inputs for S3 setup.
            - `override.ts`: Customizes the S3 CloudFormation template. This is crucial for:
                - Setting up a service role (`HealthScribeServiceRole`) that HealthScribe can assume to access the S3 bucket.
                - Granting authenticated users `iam:PassRole` permissions for this service role.
                - Modifying S3 public access policies for the bucket.
        - **`/amplify/backend/function/addBucketLogging/`**: Contains a Lambda function.
            - `src/index.js`: The Lambda code, which is a custom resource used during CloudFormation deployment to enable server access logging for the main S3 bucket.
            - `addBucketLogging-cloudformation-template.json`: The CloudFormation template for this Lambda function.
        - **`/amplify/backend/custom/addBucketLogging/`**: Defines a custom CDK resource.
            - `cdk-stack.ts`: A CDK stack that creates a separate S3 bucket for storing access logs and uses the `addBucketLogging` Lambda function to configure the main storage bucket to log to this new logging bucket.
        - **`/amplify/backend/awscloudformation/override.ts`**: Allows overriding the root CloudFormation stack generated by Amplify. This is used to add IAM policies to the authenticated user role, granting permissions for:
            - AWS HealthScribe actions (`transcribe:StartMedicalScribeJob`, `transcribe:GetMedicalScribeJob`, etc.).
            - Amazon Polly actions (`polly:SynthesizeSpeech`).
            - Amazon Comprehend Medical actions (`comprehendmedical:DetectEntitiesV2`, `comprehendmedical:InferICD10CM`, etc.).
    - `cli.json`: Amplify CLI configuration.
    - `/amplify/hooks/post-push.js`: A script that runs after `amplify push`. It reads the `HealthScribeServiceRoleArn` from the Amplify outputs and writes it to `/src/aws-custom.json` so the frontend can use it when starting HealthScribe jobs.

- **`/src`:** Contains the frontend React application code.

    - `main.tsx`: The main entry point for the React application. It sets up routing, context providers, and renders the `App` component.
    - **`/src/components`:** Reusable UI components.
        - `App/App.tsx`: The root React component, defines the overall layout using Cloudscape's `AppLayout`, manages routing based on authentication status.
        - `Auth/Auth.tsx`: Provides the sign-in/sign-up modal using `@aws-amplify/ui-react`'s `Authenticator`.
        - `Conversation/`: Components related to displaying a single HealthScribe job's results (transcript, insights, audio player).
        - `Conversations/`: Components for listing, filtering, and managing existing HealthScribe jobs.
        - `NewConversation/`: Components for creating a new HealthScribe job (uploading/recording audio, setting parameters).
        - `GenerateAudio/`: Components for using Amazon Polly to create synthetic audio.
        - `Settings/`: Component for managing application settings (like AWS region).
        - `SideNav/`, `TopNav/`: Navigation components.
        - `Welcome/`: The landing page components.
    - **`/src/hooks`:** Custom React hooks for reusable logic.
        - `useAudio.ts`: Manages audio playback state with `wavesurfer.js`.
        - `useLocalStorage.ts`: A generic hook for persisting state to browser local storage.
        - `useNotification.tsx`: Manages flashbar notifications and progress bars.
        - `useS3.ts`: Provides S3 bucket name and metadata for uploads.
    - **`/src/store`:** Global state management using React Context.
        - `appSettings/`: Manages application-wide settings (e.g., AWS region, Comprehend Medical enablement).
        - `appTheme/`: Manages UI theme (light/dark mode, density).
        - `auth/`: Manages authentication state (user, authentication status).
        - `notifications/`: Manages global notifications.
    - **`/src/types`:** TypeScript type definitions for data structures (HealthScribe output, Comprehend Medical results, etc.).
    - **`/src/utils`:** Utility functions.
        - `ComprehendMedicalApi/index.ts`: Functions for interacting with the Amazon Comprehend Medical API.
        - `HealthScribeApi/index.ts`: Functions for interacting with the AWS HealthScribe API.
        - `PollyApi/index.ts`: Functions for interacting with the Amazon Polly API.
        - `S3Api/index.ts`: Functions for interacting with Amazon S3 (uploads, downloads, presigned URLs).
        - `Sdk/index.ts`: Helper functions for AWS SDK configuration (credentials, region).
    - `aws-custom.json`: (Generated by `post-push` hook) Stores the `HealthScribeServiceRoleArn`.
    - `amplifyconfiguration.json`: (Generated by Amplify) Contains the configuration for Amplify categories (auth, storage).

- **`/docs`:** Contains documentation files, including this explanation.
- **`/images`:** Contains images used in documentation and the UI.
- **`/public`:** Static assets served directly by Vite.

## 3. Main Application Flow

1.  **Entry Point (`/src/main.tsx`):**

    - Initializes the React application.

        - `Authenticator.Provider` from `@aws-amplify/ui-react` for Amplify UI authentication components.

    - Renders the main `App` component and a `Toaster` for notifications.

2.  **Root Component (`/src/components/App/App.tsx`):**

    - Uses `useAuthContext()` to get the user's authentication status.
    - Defines the main application layout using Cloudscape's `<AppLayout>`. This includes:
        - `<TopNav />`: The top navigation bar.
        - `<SideNav />`: The side navigation panel (hidden if not authenticated).
        - `<Breadcrumbs />`: Breadcrumb navigation.
        - `content`: The main content area, which renders different components based on the current route.
        - `<Flashbar />`: Displays notifications from `useNotificationsContext()`.
    - **Routing:** Uses `react-router-dom`'s `<Routes>` and `<Route>` components.
        - If the user is authenticated, routes like `/conversations`, `/conversation/:conversationName`, `/new`, `/generate`, `/settings` are available.
        - If not authenticated, all paths redirect to the `Welcome` component.
        - Components for routes are lazy-loaded using `React.lazy()` for better initial load performance, with `<Suspense fallback={<SuspenseLoader />}>` handling the loading state.

3.  **Navigation:**
    - `/src/components/SideNav/SideNav.tsx`: Provides links to major sections like "Conversations", "New Conversation", "Settings".
    - `/src/components/TopNav/TopNav.tsx`: Contains the application title, settings for theme/density, and the Sign In/User Profile dropdown.

## 4. Authentication and Amplify/Cognito Logic

Authentication is managed by **Amazon Cognito**, provisioned and configured via **AWS Amplify**.

- **Configuration (`/amplify/backend/auth/healthScribeDemoAuth/`):**

    - `cli-inputs.json`: Defines the Cognito User Pool and Identity Pool settings.
        - Users sign up and sign in with email.
        - Email verification is enabled.
        - MFA is off by default.
    - `override.ts`: Customizes the CloudFormation template for Cognito. In this project, it's used to shorten the default validity periods for refresh, access, and ID tokens for security purposes in a demo environment.
        - `resources.userPoolClient.refreshTokenValidity = 1; // days`
        - `resources.userPoolClientWeb.accessTokenValidity = 1; // hours`

- **Frontend Integration:**

    - **Auth Context (`/src/store/auth/index.tsx`):**

        - Uses the `useAuthenticator` hook from `@aws-amplify/ui-react` to get the current authentication status (`authStatus`), user object (`user`), and `signOut` function.
        - Provides these values (`isUserAuthenticated`, `user`, `signOut`) to the rest of the application via `AuthContext`.
        - `Amplify.configure(config)` is called here, loading `amplifyconfiguration.json` which contains the Cognito User Pool ID, App Client ID, Identity Pool ID, etc.

    - **Auth UI (`/src/components/Auth/Auth.tsx`):**

        - This component renders the `@aws-amplify/ui-react` `<Authenticator />` component within a Cloudscape `<Modal />`.
        - The `Authenticator` handles the entire sign-up, sign-in, forgot password, and email verification flow.
        - It's themed to match Cloudscape's visual style using `ThemeProvider` and custom tokens.
        - The modal is shown when the "Sign In" button in `/src/components/TopNav/TopNav.tsx` is clicked.

    - **Top Navigation (`/src/components/TopNav/TopNav.tsx`):**
        - Displays a "Sign In" button if the user is not authenticated. Clicking it sets `authVisible` to `true`, showing the `Auth.tsx` modal.
        - If authenticated, it displays the user's email and a dropdown with a "Sign out" option, which calls the `signOut` function from `AuthContext`.

- **IAM Roles and Permissions:**

    - When a user signs in, they assume an IAM role associated with the Cognito Identity Pool's authenticated users.
    - `/amplify/backend/awscloudformation/override.ts` modifies this authenticated role to grant necessary permissions to call HealthScribe, Comprehend Medical, and Polly.
    - Crucially, it also grants `iam:PassRole` permission for the `HealthScribeServiceRole` (defined in `/amplify/backend/storage/healthScribeDemoStorage/override.ts`). This allows the frontend, acting on behalf of the authenticated user, to specify this service role when creating a HealthScribe job. HealthScribe then assumes this role to access the audio in S3 and write results back to S3.

- **Data Access Role (`/src/aws-custom.json`):**

    - The ARN of the `HealthScribeServiceRole` is needed by the frontend when calling `StartMedicalScribeJob`.
    - The `/amplify/hooks/post-push.js` script runs after `amplify push`. It reads this ARN from the CloudFormation stack outputs (specifically from the storage stack where it's defined) and writes it into `/src/aws-custom.json`.
    - The frontend then imports this JSON file to get the role ARN. See `/src/components/NewConversation/NewConversation.tsx`:

        ```typescript
        import amplifyCustom from '../../aws-custom.json';

        // ...
        const jobParams: StartMedicalScribeJobRequest = {
            // ...
            DataAccessRoleArn: amplifyCustom.healthScribeServiceRole,
            // ...
        };
        ```

## 5. AWS HealthScribe Integration

The application interacts with AWS HealthScribe to transcribe audio and generate clinical documentation.

- **API Interaction (`/src/utils/HealthScribeApi/index.ts`):**

    - This utility file centralizes all calls to the HealthScribe service using the AWS SDK for JavaScript v3 (`@aws-sdk/client-transcribe`).
    - `getTranscribeClient()`: Creates and configures the `TranscribeClient` with the region from app settings and user credentials.
    - `startMedicalScribeJob(params)`: Calls the `StartMedicalScribeJobCommand`.
        - Takes parameters like `MedicalScribeJobName`, `DataAccessRoleArn` (from `aws-custom.json`), `OutputBucketName`, `Media.MediaFileUri`, and `Settings` (including `ChannelIdentification` or `MaxSpeakerLabels`, and `ClinicalNoteGenerationSettings`).
    - `getHealthScribeJob(params)`: Calls `GetMedicalScribeJobCommand` to fetch the status and details of a job.
    - `listHealthScribeJobs(params)`: Calls `ListMedicalScribeJobsCommand` to get a list of jobs, with optional filtering.
    - `deleteHealthScribeJob(params)`: Calls `DeleteMedicalScribeJobCommand`.
    - API call timings can be logged to the console if enabled in settings, using `printTiming()` from `/src/utils/Sdk/index.ts`.

- **Creating a New Conversation (`/src/components/NewConversation/NewConversation.tsx`):**

    - This component provides a form to start a new HealthScribe job.
    - **Job Name:** User input, validated by `verifyJobParams` in `/src/components/NewConversation/formUtils.ts`.
    - **Note Type:** User selects SOAP (`HISTORY_AND_PHYSICAL`) or GIRPP.
    - **Audio Identification:**
        - `speakerPartitioning`: User specifies `maxSpeakers`.
        - `channelIdentification`: User maps Channel 1 to Clinician or Patient.
    - **Audio Source:**
        - **Upload Audio (`/src/components/NewConversation/Dropzone.tsx`):**
            - Uses `react-dropzone` to allow users to drag-and-drop or select an audio file.
            - Validates file type and size.
            - The selected `File` object is stored in the `filePath` state.
        - **Live Record (`/src/components/NewConversation/AudioRecorder.tsx`):**
            - Uses `wavesurfer.js` with the `RecordPlugin` to record audio from the user's microphone.
            - Displays a waveform of the live recording.
            - Once stopped, the recorded audio is converted to a `File` object and stored in the `recordedAudio` state, which then updates `filePath`.
    - **Submission Process (`submitJob` function):**
        1.  Validates job parameters.
        2.  Displays a progress bar using `updateProgressBar` from `NotificationsContext`.
        3.  **Uploads Audio to S3:**
            - Uses `fileUpload` from `/src/utils/S3Api/index.ts`.
            - `fileUpload` internally uses `uploadData` from `aws-amplify/storage`.
            - The S3 key includes a UUID generated by `useS3` hook to ensure uniqueness: `uploads/HealthScribeDemo/${uuid4()}/${fileName}`.
            - The `s3UploadCallback` updates the progress bar during the S3 upload.
        4.  **Starts HealthScribe Job:**
            - Calls `startMedicalScribeJob` from `/src/utils/HealthScribeApi/index.ts` with the constructed parameters, including the S3 URI of the uploaded audio and the `DataAccessRoleArn`.
            - Updates the progress bar upon success or failure.
            - Navigates to the `/conversations` page after a short delay on success.

- **Viewing a Conversation (`/src/components/Conversation/Conversation.tsx`):**

    - Fetches the `conversationName` (which is the `MedicalScribeJobName`) from URL parameters.
    - **`getJob` function (in `useEffect`):**
        1.  Calls `getHealthScribeJob` to get job details (`MedicalScribeJob`).
        2.  If the job is `COMPLETED`, it retrieves the `TranscriptFileUri` and `ClinicalDocumentUri` from `MedicalScribeJob.MedicalScribeOutput`.
        3.  Uses `getObject` from `/src/utils/S3Api/index.ts` to download the transcript and clinical document JSON files from these S3 URIs.
        4.  Parses the JSON content and stores it in `transcript` and `summary` states.
    - **Layout:**
        - `<ConversationHeader />`: Displays job name and download/view output buttons.
        - `<TopPanel />`: Handles audio playback.
        - `<LeftPanel />`: Displays the transcript.
        - `<RightPanel />`: Displays insights (summarized clinical notes).

- **Audio Playback and S3 (`/src/components/Conversation/TopPanel/TopPanel.tsx`):**

    - When the component mounts and `jobDetails` are available:
        1.  It gets the `MediaFileUri` (S3 URI of the original audio) from `jobDetails`.
        2.  Uses `getS3Object` to parse the bucket and key.
        3.  Uses `getPresignedUrl` from `/src/utils/S3Api/index.ts` to generate a short-lived presigned URL for the audio file.
        4.  Initializes `wavesurfer.js` with this presigned URL to load and play the audio.
    - `wavesurfer.js` is used to display the waveform and control playback (play, pause, seek, speed).
    - It also calculates and can visually mark silences (`extractRegions.ts`) and "small talk" segments based on the transcript.

- **S3 Bucket Structure:**
    - The main S3 bucket (e.g., `healthscribe-demo-storage-dev-xxxx`) is configured by Amplify.
    - Uploaded audio files go to: `public/uploads/HealthScribeDemo/<UUID>/<filename.mp3>` (Note: `public/` prefix is for Amplify Storage access control, actual S3 key is `uploads/...`).
    - HealthScribe output (transcript and clinical document JSON) is written by HealthScribe to the root of this bucket, using the `MedicalScribeJobName` in the file path. For example:
        - `<MedicalScribeJobName>.json` (transcript)
        - `<MedicalScribeJobName>.clinical_document.json` (clinical document)
    - A separate logging bucket (e.g., `amplify-awshealthscribedemo-loggingbucket-xxxx`) stores server access logs for the main bucket.

## 6. Amazon Comprehend Medical Usage

The application uses Amazon Comprehend Medical to enhance the information extracted by HealthScribe.

- **API Interaction (`/src/utils/ComprehendMedicalApi/index.ts`):**

    - `getComprehendMedicalClient()`: Creates and configures the `ComprehendMedicalClient`.
    - `detectEntitiesFromComprehendMedical(text)`: Calls `DetectEntitiesV2Command` to extract medical entities (like medications, conditions, anatomy) from a given text. This is used on the summarized segments in the "Insights" panel.
    - `getInferredData(ontology, text)`: A wrapper function that calls:
        - `InferICD10CMCommand` for ICD-10-CM codes.
        - `InferRxNormCommand` for RxNorm codes (medications).
        - `InferSNOMEDCTCommand` for SNOMED CT codes.
          This is used for ontology linking on individual clinical entities in the transcript and on entities within the insights panel.

- **Configuration:**

    - The ability to use Comprehend Medical is controlled by a setting in `/src/components/Settings/Settings.tsx` ("Amazon Comprehend Medical" toggle), which updates `appSettings['app.comprehendMedicalEnabled']` in the `AppSettingsContext`.
    - If disabled, Comprehend Medical related UI elements show an info popover (`EnableComprehendMedicalPopover` from `/src/components/Conversation/Common/ComprehendMedical.tsx`).

- **Usage in the Transcript (`/src/components/Conversation/LeftPanel/ClinicalInsight.tsx`):**

    - When a clinical entity (identified by HealthScribe) is displayed in the transcript popover:
        - The `OntologyLinking` component (`/src/components/Conversation/Common/OntologyLinking.tsx`) is rendered.
        - `OntologyLinking` provides buttons ("Infer ICD-10-CM", "Infer RxNorm", "Infer SNOMED CT") based on the `category` of the clinical entity.
        - Clicking a button calls `handleInfer`, which in turn calls `getInferredData` with the entity's text.
        - The results (e.g., list of concepts with codes, descriptions, scores) are displayed by `OntologyLinkingData.tsx`.

- **Usage in Insights/Summaries (`/src/components/Conversation/RightPanel/RightPanel.tsx`):**
    - The "Insights" panel (RightPanel) displays the summarized clinical notes from HealthScribe.
    - **Extract Health Data Button:**
        - When clicked, `handleExtractHealthData` is triggered.
        - It iterates through each summarized segment in each section of the clinical document.
        - For each segment, it calls `detectEntitiesFromComprehendMedical` (via `/src/utils/ComprehendMedicalApi/index.ts`).
        - The extracted entities (from `DetectEntitiesV2Response`) are stored in the `extractedHealthData` state.
    - **Displaying Extracted Data (`/src/components/Conversation/RightPanel/SummarizedConcepts.tsx` and `SummaryList.tsx`):**
        - `mergeHealthScribeOutputWithComprehendMedicalOutput` (in `summarizedConceptsUtils.ts`) combines the HealthScribe summary with the `extractedHealthData` from Comprehend Medical. It maps entities to words in the summary.
        - `ExtractedHealthDataWord` (in `SummaryListComponents.tsx`) renders each word. If a word is part of an entity detected by Comprehend Medical (and above the confidence threshold set in `RightPanelSettings`), it's highlighted and a popover (`WordPopoverComprehendMedical`) shows:
            - Entity details (text, category, type, score, attributes).
            - The same `OntologyLinking` component used in the transcript, allowing users to infer ICD-10, RxNorm, or SNOMED CT codes for these Comprehend Medical-detected entities.
    - **Cost Estimation (`/src/components/Conversation/Common/ComprehendMedical.tsx` - `ComprehendMedicalNereCost`):**
        - `calculateNereUnits` (in `/src/components/Conversation/RightPanel/rightPanelUtils.ts`) estimates the number of 100-character units for the `DetectEntitiesV2` API call based on the clinical document's content.
        - `ComprehendMedicalNereCost` displays an estimated cost based on this unit count and public Comprehend Medical pricing.

## 7. Key Component Interactions

- **Creating a New Conversation (Flow Summary):**

    1.  User navigates to `/new`.
    2.  `NewConversation.tsx` renders a form.
    3.  User fills in job name, note type, audio identification settings.
    4.  User either:
        - Uploads an audio file via `Dropzone.tsx`.
        - Records audio live via `AudioRecorder.tsx`.
    5.  The chosen/recorded audio `File` is set in `filePath` state.
    6.  User clicks "Submit".
    7.  `submitJob` in `NewConversation.tsx`:
        - Validates inputs.
        - Uploads the file to S3 (via `S3Api/fileUpload` -> Amplify Storage `uploadData`).
        - Calls `HealthScribeApi/startMedicalScribeJob` with S3 URI and `DataAccessRoleArn`.
        - User is redirected to `/conversations`.

- **Viewing a Conversation (Flow Summary):**

    1.  User navigates to `/conversation/:conversationName` (e.g., from the list in `Conversations.tsx`).
    2.  `Conversation.tsx` mounts.
    3.  `useEffect` calls `getJob`:
        - Fetches job details via `HealthScribeApi/getHealthScribeJob`.
        - If `COMPLETED`, fetches transcript and summary JSON from S3 URIs (via `S3Api/getObject`).
        - Updates `jobDetails`, `transcript`, `summary` states.
    4.  `TopPanel.tsx`:
        - Gets audio S3 URI from `jobDetails`.
        - Gets a presigned URL via `S3Api/getPresignedUrl`.
        - Loads audio into `wavesurfer.js`.
    5.  `LeftPanel.tsx`:
        - Receives `transcript` data.
        - Processes transcript segments and items, mapping clinical insights to words.
        - Renders `TranscriptSegment.tsx` for each segment, which in turn renders `WordPopoverTranscript.tsx` for each word, enabling popovers with clinical entity details and ontology linking.
        - Highlights words/segments based on audio playback time (`audioTime`) or user clicks on insights.
    6.  `RightPanel.tsx`:
        - Receives `summary` and `transcript` data.
        - Renders `SummarizedConcepts.tsx`, which displays sections and summarized segments.
        - If "Extract Health Data" is clicked, calls Comprehend Medical `DetectEntitiesV2` for each summary segment.
        - `SummaryListComponents.tsx` renders words, highlighting Comprehend Medical entities and providing popovers with details and ontology linking.
        - Clicking a summarized segment in `RightPanel` updates `highlightId` state (managed by `useAudio` hook in `Conversation.tsx`), which can then highlight corresponding segments in `LeftPanel` and seek audio in `TopPanel`.

- **State Management (`/src/store/`):**
    - The application uses React Context for global state.
    - **`AuthContext`**: Manages user authentication status, user object, and sign-out function. Used by `App.tsx` to control routing and by `TopNav.tsx` for sign-in/out UI.
    - **`AppSettingsContext`**: Manages settings like AWS region, API timing, Comprehend Medical enablement. These are persisted to local storage via `useLocalStorage`. `Settings.tsx` allows users to change these. The AWS SDK clients in `/src/utils/Sdk` use these settings.
    - **`AppThemeContext`**: Manages UI theme (light/dark, compact/comfortable). Persisted to local storage. `TopNav.tsx` allows users to change this, and `App.tsx` applies the styles.
    - **`NotificationsContext`**: Manages flash messages and progress bars. `useNotification` hook provides functions `addFlashMessage` and `updateProgressBar`. Used by `NewConversation.tsx` during job submission and by various components for error/success messages. `App.tsx` renders the `Flashbar` to display these.

## 8. Other Important Files/Features

- **Amplify Backend Customization (`/amplify/backend/.../override.ts` files):**

    - These files are crucial for tailoring the Amplify-generated CloudFormation templates.
    - `auth/.../override.ts`: Modifies Cognito token validity.
    - `storage/.../override.ts`:
        - Defines the `HealthScribeServiceRole` that HealthScribe assumes.
        - Grants `iam:PassRole` for this role to authenticated users.
        - Sets S3 bucket public access blocks.
        - Outputs the `HealthScribeServiceRoleArn`.
    - `awscloudformation/override.ts`: Adds permissions to the authenticated user's IAM role for HealthScribe, Comprehend Medical, and Polly.
    - `custom/addBucketLogging/cdk-stack.ts`: A CDK stack to create a logging S3 bucket and configure the main storage bucket to log to it using a Lambda custom resource.

- **UI Components (Cloudscape Design System):**

    - The entire UI is built using components from `@cloudscape-design/components` (e.g., `AppLayout`, `Container`, `Table`, `Button`, `Modal`, `FormField`, `Select`). This ensures a consistent and accessible user experience.

- **Audio Generation (`/src/components/GenerateAudio/`):**

    - `GenerateAudio.tsx`: Allows users to create synthetic multi-speaker audio conversations.
    - Users can add lines of text and assign a Polly voice to each line.
    - Templates for common scenarios (knee problem, sleep apnea) are provided in `/src/components/GenerateAudio/templates/`.
    - `AudioLineBox.tsx`: Component for a single line of text and speaker selection.
    - **Amazon Polly Integration (`/src/utils/PollyApi/index.ts`):**
        - `getAudioBlobFromPolly({ voiceId, text })`: Calls Polly's `SynthesizeSpeechCommand` to generate an MP3 audio blob for a line of text.
        - In `GenerateAudio.tsx`, when "Download" is clicked:
            - It iterates through each `audioLine`.
            - Calls `getAudioBlobFromPolly` for each line.
            - Uses `crunker` library to fetch the audio blob, pad it with a short silence, and then concatenate all lines into a single audio buffer.
